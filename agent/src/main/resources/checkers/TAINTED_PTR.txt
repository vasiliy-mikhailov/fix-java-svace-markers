(?:prepareStatement|createStatement|execute(?:Query|Update)?|\w+(?:Query|Exec)\w*|new\s+File|Paths\.get|Path\.of|\.resolve)\s*\(
TAINTED_PTR reports a caller-controlled value — a Spring `@RequestParam`, a header, an uploaded filename — reaching a sink that *interprets* it (a JDBC statement string, a filesystem path) with no validation in between. The marker lands either on the sink call itself (Assignment5.java:44, `connection.prepareStatement(` of a string built by concatenating `username_login` and `password_login`) or on the call that forwards the still-raw parameters into the method that does the concatenating (SqlInjectionLesson5b.java:41, `return injectableQuery(login_count, userid);` — one frame above the concatenation at line 45). It is not the "unvalidated integer / index / allocation size" family: nothing here has to be numeric, and the word `PreparedStatement` on the flagged line is not evidence against the report — both sites I read prepare a statement whose text was already built by concatenation.
