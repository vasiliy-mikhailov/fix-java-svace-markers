Runtime\.getRuntime\(\)\.exec|ProcessBuilder|\.exec\s*\(
A command built from data that reaches a process launcher.

HOW IT ACTUALLY BEHAVES. `Runtime.exec(String)` does NOT run a shell. It splits the string on
whitespace with a StringTokenizer and starts the first token as a program, passing the rest as
argv. So `;`, `&&`, `|`, backticks and `$( )` chain NOTHING — they arrive as literal arguments to
the first program. So a test asserting that `"ls; touch /tmp/pwned"` creates a file WILL fail — the
file is never created — and it fails for a reason that has nothing to do with whether the marker is
real. That is the trap, because a failing test is exactly what a reproduction looks like from the
outside: the RED is real and it proves nothing.

What IS injectable through that door: an extra ARGUMENT to the program being run, and the program
itself when the first token is attacker-controlled. Demonstrate it by what the process does — how
long it blocks, what it writes, its exit status — not by a shell side-effect that cannot happen.

`Runtime.exec(String[])` and `ProcessBuilder` do not tokenise at all, so each element is one
argument and even argument injection needs the caller to have concatenated.
