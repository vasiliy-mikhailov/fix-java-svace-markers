\b\w*(?:[Ee]xecute|[Pp]repareStatement|[Qq]uery)\w*\s*\(\s*[A-Za-z_$][\w$]*\s*[,)]
A taint-flow finding, not a null-pointer one: a value that entered from the request reaches a use that INTERPRETS it — here a JDBC statement — with no validation and no parameter binding between source and sink. "PTR" is the family name, not a claim about pointers.

WHAT THE SUFFIX MEANS. `.MINOR` grades confidence in the SOURCE — how certain the analyser is that the value is caller-controlled — not the damage at the sink. An implicitly bound parameter carrying no annotation is a less certain source than an explicitly annotated one while being just as attacker-controlled, so a `.MINOR` marker can sit on a rawer sink than a Critical one. Plain TAINTED_PTR and TAINTED_PTR.COOKIE (source is a cookie value) are separate checkers with their own notes.

THE ANCHOR IS OFTEN NOT THE SINK: frequently it is the forwarding call that hands the still-raw value one frame down, and it may contain no SQL at all. It can equally land on a parameter declaration, or on a line that is blank in your checkout because the scan ran against a different revision. Read the enclosing method in both directions before settling "no sink on this line, not a defect".

HOW YOU MAKE IT VISIBLE.
THE OBSERVABLE IS STORE STATE, NOT THE RESPONSE. Code of this shape commonly wraps the call in a catch-everything block and returns the same body whether the statement ran, ran destructively, or threw — so an assertion on status code or response text can watch a successful destructive injection and call it a failure. Assert on what the database now contains: a table that is gone, a privilege granted, rows that should never have come back, read over a connection you open yourself. Where connections are proxied and scoped per caller, verify through the same route so the check lands where the write went.

GET THE POLARITY RIGHT. Asserting that the injection succeeds is green before any fix and stays green after. Assert the safe property, so the test fails on the current code and passes once the value is bound or validated.

WHAT GOES WRONG HERE.
"PTR" reads as pointer, so agents test the null path. An omitted unannotated parameter binds to null, the catch-everything block swallows the dereference, nothing escapes — and that construct belongs to a null-dereference checker anyway.

Importing the shell-injection habit. When the parameter IS the whole statement, metacharacter chaining is beside the point and the payload that proves anything is a bare destructive or DDL statement. Choosing a payload by analogy instead of by reading what the sink executes is how a demonstration ends up unable to fail for the right reason.

Asserting the marker back at itself, and mistaking the shape of a fix. Swapping a plain statement for `prepareStatement(theWholeString)` binds nothing: when the entire text is caller-supplied there is no structure left to parameterise.

Treating "flagged" as "uniquely bad". The identical construct usually appears unflagged elsewhere in the same tree; a missing marker on a sibling is not a verdict about the sibling, and a marker here is not evidence this site differs from them.

Deciding from the reputation of the code rather than the flagged line. Some code interprets caller input on purpose, but intent has to be shown by something checked in that REQUIRES the interpretation — documentation instructing a caller to send this payload to this path, a test asserting the attack succeeds. A package or class named for a mitigation is not that evidence.
